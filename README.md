# WeatherSphere AI

A full multi-page weather intelligence platform built with Flask, SQLite,
Chart.js and the free, keyless **Open-Meteo** API. No API keys or sign-ups
required — it runs the moment you install the dependencies.

## Features

- **Landing page** — hero search, live suggestions, trending cities, feature showcase
- **City weather page** (`/weather/<city>`) — current conditions, humidity, wind,
  visibility, pressure, UV index, AQI, sunrise/sunset
- **Hourly forecast** — scrollable 24-hour cards + Chart.js temperature line
- **7-day forecast** — daily min/max, condition, rain probability
- **Analytics dashboard** (`/analytics`) — 14-day (7 past + 7 forecast) temperature,
  wind, precipitation and AQI charts, per city
- **Compare cities** (`/compare`) — head-to-head metrics and a bar chart
- **User dashboard** (`/dashboard`) — favorites, search history, most-searched city,
  total searches
- **AI insight engine** (rule-based, no external LLM needed) — weather summary,
  outfit advice, travel advice, health advisory, activity suggestion, and
  rain/storm/heatwave risk scores
- **Alerts** (`/alerts`) — auto-generated rain/storm/heatwave/AQI alerts
- **Favorites, search history, geolocation, voice search** (Web Speech API),
  **PDF export**, **shareable links**, **dark/light mode**, **auto-refresh**

## Tech stack

Flask · SQLite · Requests · Jinja2 · HTML5/CSS3 · vanilla JS · Chart.js ·
Font Awesome · ReportLab (PDF generation) · Open-Meteo (weather, geocoding,
air quality, historical archive — all free, no key needed)

## Setup

```bash
cd weather_dashboard
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Visit **http://localhost:5000**. The SQLite database (`database/weathersphere.db`)
and its tables are created automatically on first run.

## Database schema

- `users` — anonymous browser identity (cookie-based UUID), theme preference
- `search_history` — every city searched, per user
- `favorite_cities` — starred cities, per user
- `weather_alerts` — generated rain/storm/heatwave/AQI alerts, per city
- `weather_reports` — lightweight snapshot log used for the report/export flow

## Notes on the "AI" features

The AI Weather Summary, Outfit, Travel, Health, Activity and Risk modules are
generated by a deterministic rule engine in `app.py` (`build_ai_insights`)
driven by live temperature, humidity, wind, UV and AQI data — there is no
external LLM call, so the app works fully offline from an AI-services
standpoint and has zero extra cost or latency. If you want to swap in a real
LLM for richer natural-language summaries, that function is the integration
point.

## Notes on data

All weather data comes from Open-Meteo's free endpoints:
- Geocoding: `https://geocoding-api.open-meteo.com/v1/search`
- Forecast: `https://api.open-meteo.com/v1/forecast`
- Air quality: `https://air-quality-api.open-meteo.com/v1/air-quality`
- Historical archive (used for the 7-day-past analytics charts):
  `https://archive-api.open-meteo.com/v1/archive`

No API key is required for any of these. If you'd rather use OpenWeatherMap,
swap the URLs/params in the fetch functions near the top of `app.py`.
